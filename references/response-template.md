# 回复审稿意见与投稿材料模板

## 一、回复审稿意见（返修阶段用）

### 结构（逐条回应制）

1. **开场总述**（2–3 句）：感谢编辑与审稿专家；概述本轮修改的主要方向与幅度；如有未采纳意见，预告理由。
2. **逐条回应**：一条意见 = 一个区块，格式固定：
   > **意见 1**：（复述审稿意见原文或要点）
   >
   > **回应**：感谢指正……（同意并说明如何改 / 部分同意并说明折中 / 有依据的商榷）
   >
   > **修改位置**：第 X 节第 X 段（修改后见第 X 页第 X 段）
3. **收尾**：再次致谢；声明修改稿与批注版一并提交。

### 三类情况的处理范式

| 情况 | 写法要点 |
|---|---|
| 同意并修改 | 直接说明改法 + 位置；不辩解、不赘述 |
| 部分同意 | 先明确认可意见的合理部分，再说明保留部分的原因（拿证据/文献/数据说话） |
| 不同意 | 礼貌商榷：先复述对方的关切点表示理解，再给出具体理由（标准条款、数据、文献）；不情绪化，不空言"我们认为" |

### 纪律

- 每条意见都必须回应，哪怕只是"已按要求补做/已在 X 处说明"
- 修改位置要具体到节/段，让审稿人能核对
- 不做无原则让步：为迎合而改坏研究逻辑，是返修阶段的典型错误
- 反谄媚：感谢语克制（"感谢指正"即可），不堆"非常宝贵""受益匪浅"

### 提交前机器核对（`scripts/response_check.py`）

把审稿意见（编辑部返回的原始意见页）与回复信各存一份，跑：

```
python scripts/response_check.py --reviews 审稿意见.docx --response 回复信.docx
```

它核三件事，并按档位输出（🔴 硬伤 / 🟡 待核对 / ✅ 完整），退出码 1 = 有硬伤：

1. **条数对齐**：按编号集合比对（不只是计数），漏回了哪几条、回复信多出哪几条，直接点名；
2. **三件套**：每个回应区块是否含「意见（复述）/ 回应 / 修改位置」；
3. **位置精确**：位置是否精确到节/段/页/表/图——只写"已修改""见修改稿"报🟡待核对。

支持 `.docx`（正文段落 + 表格，表格按表头「审稿意见/回应/修改位置」分列）、`.md`、`.txt`（含 markdown 表格）。**文件最好按上面的逐条结构组织**：意见文件用「意见 N：」编号、回复信用「**意见 N**／**回应**／**修改位置**」三标签，机器才能逐条对上；自由书写的回复信只会报"未识别到逐条结构"，交人工核对（不误报漏回）。

合成测试样例（无真实样例时按本模板的规范结构造）：

- 意见文件：`意见 1：…` × 3 条（含图号、样本量、方法说明三类典型意见）；
- 回复信：开场总述 + 每条「**意见 N**（复述）→ **回应**（感谢指正…已改）→ **修改位置**（第 2.1 节第 3 段）」+ 收尾致谢；
- 反样例：漏掉一条 / 位置只写"已修改" / 整篇无标签的感谢信——分别验证🔴漏回、🟡位置不精确、🟡未识别到结构三条路径。

## 二、投稿材料（该刊邮箱投稿）

### 投稿邮件正文（模板骨架）

> 尊敬的编辑老师：
>
> 您好！现向贵刊投递论文《××××××》（约 ×× 字），恳请审阅。
>
> 论文围绕____问题，采用____方法开展研究，主要发现为____，并提出____。论文选题与本刊「信息服务」（或实际栏目）方向相关。
>
> 随邮件附：论文稿件（Word）、查重报告、作者简介。全体作者均阅读并同意投稿，无一稿多投。
>
> 盼复为感！
>
> 作者：×××（单位、联系方式）

### 作者简介要素

姓名、性别、出生年、单位、职称/学位、研究方向、联系方式（简版 1–2 行即可）。

### 投稿前最后清点（详见 checklists.md）

- [ ] 稿件 + 查重报告（<10%）+ AIGC 检测（<10%）+ 作者简介，四件齐
- [ ] 署名与顺序已在全体作者间确认（录用后不可改）
- [ ] 通讯作者的联系方式准确
